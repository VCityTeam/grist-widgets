# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A collection of independent [Grist](https://www.getgrist.com/) custom widgets, one per top-level folder. Each widget is a self-contained pair of static files (`index.html`, `app.js`) with no build step, package manager, or test suite — dependencies are pulled from CDN and the files are loaded directly by Grist as a custom widget. The whole repo is deployed as-is to GitHub Pages (`.github/workflows/static.yml`), so a new widget just needs its own folder plus a line in `README.md`; each widget's URL is `https://vcityteam.github.io/grist-widgets/<folder>/index.html`.

There's no local dev server or build command for any widget. To test changes to a widget:

1. Serve the repo root over HTTP (e.g. `python3 -m http.server`) since Grist widgets must be loaded via URL, not `file://`.
2. In a Grist document, add a Custom Widget pointing at `http://<host>/<folder>/index.html`, and map its declared columns to columns in a table.
3. Verify the widget's read/write sync: editing data in the widget writes back to Grist, and switching the selected record loads that record's data.

For a quick check without a real Grist host, load the widget's `index.html` in a browser (e.g. via Playwright) with the CDN `grist-plugin-api.js` request intercepted/stubbed (a real one installs its own `window.grist` via postMessage RPC and will clobber a plain stub set via `addInitScript`), fire `window.grist`'s `onRecord`/`onRecords`/`onOptions`/`on('message', ...)` handlers manually with fake data, then interact with the DOM directly (set values, dispatch events, click buttons) and assert on both the DOM and any `docApi.applyUserActions` calls captured by the stub.

## Widgets

### markdown-mermaid

A Markdown editor with embedded Mermaid diagram support. It shows a textarea (left, 30% width) for typing Markdown (which may contain ` ```mermaid ` fenced code blocks) and a pan/zoomable rendered canvas (right, 70% width) showing the Markdown as HTML with each Mermaid block replaced by its rendered SVG. Edits are synced live to a Grist table column via the Grist Plugin API. Dependencies: `grist-plugin-api.js`, `mermaid`, and `marked` from jsdelivr.

- **index.html** — layout/styling only (flex split-pane), loads `grist-plugin-api.js`, `mermaid`, and `marked` from CDN, then `app.js` as a module.
- **app.js** — all behavior, in a few small blocks:
  - **Zoom & pan**: mouse wheel scales (`scale`, clamped 0.1–5), drag pans (`translateX`/`translateY`); both are combined into a single CSS transform on `#diagram` via `updateTransform()`.
  - **`renderContent(text)`**: converts the editor text to HTML via `marked.parse()` and sets it as `#diagram`'s content, then calls `renderMermaidBlocks()` to walk the resulting `code.language-mermaid` elements (marked's default class for a ` ```mermaid ` fence) and replace each with its rendered SVG via `mermaid.render()`. Diagrams that fail to render are left in place as their raw source (styled via `.mermaid-error`) rather than the whole render being discarded, and every failing block's error message is collected and shown in `#error` — this preserves the original design's flicker-avoidance while now working per-diagram instead of for the whole document.
  - **Grist sync**: `grist.ready()` declares a required `markdown` column (`columns: [...]`) — this is what lets Grist offer column mapping in the Creator Panel and correctly link the widget to cell/row selection; without it, `mappings` passed to callbacks is never populated. `grist.onRecord()` fires when the selected record changes — it only overwrites the editor's contents if the editor isn't currently focused (`document.activeElement !== editor`), so the widget doesn't clobber in-progress typing. `grist.onRecords()` provides a startup fallback: if no record has arrived via `onRecord` yet (`currentRecordId === null`), it shows the first row whose mapped column isn't empty, so the widget isn't blank before any cell is selected. Both handlers route through `loadRecord()`/`getMappedColumn()` to share this logic. On every editor `input` event, the widget both re-renders locally and pushes the new value back to Grist via `grist.selectedTable.update()`, keyed on `currentRecordId`.

### geocoding-map

Geocodes an `Address` column via the public [Nominatim](https://nominatim.org/) API (`nominatim.openstreetmap.org/search`, `format=jsonv2&extratags=1&polygon_geojson=1`) and visualizes the results live on a [Leaflet](https://leafletjs.com/) map, either as points (`Latitude`/`Longitude`) or as arbitrary GeoJSON geometry (`GeoJson`) — unlike [gristlabs/grist-widget's map widget](https://github.com/gristlabs/grist-widget/tree/master/map), which only supports points and doesn't geocode. Layout is a fixed-width status/log panel (left) and the map (right, `#map-container`).

- **index.html** — panel + map layout/styling only, loads `grist-plugin-api.js` and `leaflet` from CDN, then `app.js` as a module.
- **app.js** — all behavior, in two halves that share `grist.onRecord`/`onRecords` and the `Latitude`/`Longitude`/`GeoJson` fields:
  - **Geocoding half** (ported from the geocoder's original standalone widget): `geocodeQuery(address)` calls Nominatim's `/search` endpoint and returns the top match (or `null`). `AdminLevel` comes from `extratags.admin_level`, an OSM tag that only exists on `boundary=administrative` results (cities, regions, countries) — it's `null` for street addresses and POIs, which is expected, not a bug. `AddressRank` is Nominatim's own `place_rank` field (0–30). `GeoJson` is the feature's `geojson` field (point/line/polygon geometry depending on the matched feature), stringified for storage in a Grist Text column. The "Geocode this record" button always geocodes the currently selected record (`force: true`, bypassing the cache). Auto-scan (`scan`/`scanOnNeed`) mirrors gristlabs' map widget pattern — bulk geocoding only runs if the optional `Geocode` boolean column is mapped (opt-in), and only for records where it's checked; `GeocodedAddress` caches the last address looked up so unchanged records aren't re-geocoded every sync, and requests are throttled to one per second (`REQUEST_DELAY_MS`) per Nominatim's usage policy. `mappedUpdate()` builds the `docApi.applyUserActions` payload using only the output fields actually mapped in the Creator Panel.
  - **Map half** (ported from the map's original standalone widget): `recordToFeature()` turns a mapped record into a GeoJSON Feature, preferring a parsed `GeoJson` field and falling back to a `Latitude`/`Longitude` point; records with neither are skipped (shown in `#status`) rather than erroring. `rebuildLayer()` redraws the whole `L.geoJSON` layer whenever `onRecords` fires and fits the map to its bounds. `selectFeature()` just restyles/pans to the given row's layer without rebuilding, so it doesn't fight the user's pan/zoom; it's used both by `onRecord` (cursor moved in Grist) and by clicking a map feature (`grist.setCursorPos`, gated by `allowSelectBy`).
  - **Why one widget, not two**: a geocoded record's `Latitude`/`Longitude`/`GeoJson` are written back to Grist via `applyUserActions`, which round-trips through `onRecord`/`onRecords` — so the same handlers that redraw the map on a normal Grist edit also redraw it right after a geocode, with no separate "push to map" step needed.

### print-labels-html

A fork of [gristlabs/grist-widget's print labels widget](https://github.com/gristlabs/grist-widget/tree/master/printlabels), reimplemented without Vue to match this repo's other widgets, that renders each label as sanitized HTML (`DOMPurify.sanitize()`) instead of Vue's auto-escaped `{{ }}` text interpolation — so a `LabelHtml` cell can contain formatting, images, or explicit `<br>`/`<p>` line breaks instead of only plain text. Read-only (`requiredAccess: 'read table'`); nothing is written back to Grist.

- **index.html** — layout/styling only, adapted near-verbatim from the original's `printlabels.css` (label sheet geometry per template, `--grist-theme-*` variables, print media query), loads `grist-plugin-api.js` and `dompurify` from CDN, then `app.js` as a module.
- **app.js** — all behavior:
  - `TEMPLATES` mirrors the original's six fixed sheet layouts (`labels8`…`labels80`) plus one addition, `badge1` (1 per sheet, a 7.5"×10" badge filling the page) — each an `{id, name, perPage}` with matching `.page-<id>`/`.label-<id>` CSS rules in `index.html`; `findTemplate()` looks one up by id, falling back to `labels30`.
  - `arrangeLabels(labels, template, blankCount)` paginates the flat label list into `perPage`-sized pages, padding the front with `blankCount` empty labels (for pre-printed sheets missing a few labels) and the last page's tail so the CSS grid always stays full — ported as-is from the original.
  - `buildLabels(records)` expands each record into `LabelCount` (optional, `parseFloat`-parsed, defaults to 1) copies of its `LabelHtml` value, same repeat-count behavior as the original.
  - `renderPages()` builds the page/label DOM directly (no framework) and sets each label's content via `content.innerHTML = DOMPurify.sanitize(label)` — the one substantive behavior change from upstream, which sets `label-content`'s `textContent` via Vue and relies on CSS `white-space: pre-wrap` for line breaks; here whitespace is left to normal HTML rules since the column is expected to contain real markup.
  - Template choice and `blanks` are persisted via `grist.widgetApi.setOption()` and reloaded in `grist.onOptions()`, same as the original's `save()`; `updateSize()` scales the on-screen (non-print) preview to fit the window width via the `--page-scaling` CSS var, recomputed on `resize` and after every render.

### codes-siret

Looks up companies via the French [Recherche d'entreprises](https://recherche-entreprises.api.gouv.fr/) API (`/search?q=…&per_page=1`, CORS-enabled, no key) and writes the result back to Grist. Structured like geocoding-map's geocoding half, but panel-only (no map). Originally ported from a Node data-loader helper (`queryAndFormatRE`), stripped of its pino/d3 dependencies.

- **index.html** — panel layout/styling only (query, lookup button, "Prefer head office" checkbox, results table, error, log), loads `grist-plugin-api.js` from CDN, then `app.js` as a module.
- **app.js** — all behavior:
  - `OUTPUT_FIELDS` is the single source of truth for output columns: each entry's `name`/`title`/`type` feeds both `grist.ready({columns})` and the panel's results table, and its `get(result, etablissement)` pulls the value from the API response. API coordinates are strings, so they go through `toNumber()`.
  - `selectEtablissement()` decides which establishment's location data is used: the one whose SIRET matches the query exactly (if the query is a 14-digit SIRET), otherwise the head office (`siege`), or `matching_etablissements[0]` when the `useSiege` widget option (persisted via `grist.widgetApi.setOption`) is off. Company-level fields (SIREN, name, legal category, head office SIRET) don't depend on this choice.
  - `lookupRecord()` mirrors geocoding-map's `geocodeRecord()`: the `LookedUpQuery` column caches the last query so unchanged records aren't re-queried, and `mappedUpdate()` writes only mapped output fields (via `grist.selectedTable.update`). Unlike geocoding-map, a network/HTTP error writes nothing and isn't cached, so the record is retried on a later scan; only a definitive "no match" clears the outputs. Auto-scan only runs when the optional `Lookup` bool column is mapped, for checked records, throttled by `REQUEST_DELAY_MS` (the API allows 7 req/s).

### api-enseignement-sup

Looks up French public research structures by RNSR number (`numero_national_de_structure`), acronym (`sigle`), or full name (`libelle`) in the [data.enseignementsup-recherche.gouv.fr](https://data.enseignementsup-recherche.gouv.fr) Opendatasoft API (dataset `fr-esr-structures-recherche-publiques-actives`, `/api/explore/v2.1/catalog/datasets/<id>/records?where=…&limit=1`, CORS-enabled, no key) and writes the result back to Grist. Same structure as codes-siret, minus the head-office option. Originally ported from a Node data-loader helper (`queryAndFormatESR`), stripped of its pino dependency.

- **index.html** — copy of codes-siret's panel layout (query, lookup button, results table, error, log), loads `grist-plugin-api.js` from CDN, then `app.js` as a module.
- **app.js** — all behavior, mirroring codes-siret's `OUTPUT_FIELDS` / `lookupRecord()` / `scan()` / `mappedUpdate()` design:
  - `searchQuery()` builds a single ODSQL `where` clause OR-ing `lower(<field>)="<lowercased query>"` over `SEARCH_FIELDS`, since ODSQL `=` is case-sensitive and the fields mix cases (RNSR numbers and acronyms are uppercase, names are mixed). Matching is exact (not `like`/full-text) so a write-back only happens for an unambiguous identifier. The query is embedded via `odsqlString()`, which backslash-escapes `\` and `"`. `normalizeQuery()` only trims; the cached `LookedUpQuery` is the trimmed query.
  - A query can match several structures (acronyms are not unique — e.g. `DRCI` matches 13). Up to `SEARCH_LIMIT` candidates are fetched and ranked by `matchRank()`, which prefers an RNSR match over an acronym match over a name match; ties keep the API's order, and are reported in the log with the RNSR number that was used. The matched RNSR number is itself an output field (`NumeroStructure`), so name/acronym lookups record which structure was picked.
  - Many API fields are arrays; `joinList()` stores them in Text columns joined with `LIST_SEPARATOR` (`; `). Parallel arrays (`tutelles`, `sigles_des_tutelles`, `siret_des_tutelles`, …) are kept in order and not deduplicated so their entries line up across columns; only `label_numero`, which repeats the same label, is deduplicated. `responsables()` zips the name/first name/title arrays into `Prénom NOM (TITRE)` entries. `panel_erc` is a single description the API splits on commas, so it's rejoined with `, ` and prefixed with `code_panel_erc`.
  - Requests are spaced by `REQUEST_DELAY_MS` (500 ms, as in the original loader) during auto-scan.

### schema-er-diagram

Renders the Grist document's own schema as a Mermaid `erDiagram`: one entity per table, one attribute per column (`<type> <colId> "<header> · formula"`). Read-only, but needs `requiredAccess: 'full'` because the schema comes from `grist.docApi.fetchTable()` on the `_grist_Tables` / `_grist_Tables_column` metadata tables. Declares no columns. Keys and relationships (e.g. from `Ref:` columns) are deliberately not drawn yet.

- **index.html** — toolbar (table selector, refresh, show/copy source, reset view) above a pan/zoom canvas and a hideable read-only source textarea; loads `grist-plugin-api.js` and `mermaid@11` from CDN, then `app.js` as a module.
- **app.js** — all behavior:
  - `readSchema()` fetches both metadata tables (column-oriented, converted by `toRows()`), drops summary tables and `GristHidden_*` import tables (`isUserTable()`) and internal columns (`manualSort`, `gristHelper_*`), and orders columns by `parentPos`.
  - `buildErDiagram()` emits the Mermaid source. Mermaid ER attribute types/names only accept `[A-Za-z0-9_-]` plus `()`/`[]`, so `mermaidType()` turns `Ref:People` / `DateTime:Europe/Paris` into `Ref(People)` / `DateTime(Europe_Paris)`. The column header (label) goes in the attribute's quoted comment only when it differs from the colId, with `"` replaced by `'`.
  - The table selector offers the linked table (`grist.selectedTable.getTableId()`, the default), all tables, or any single table; the choice is persisted with `grist.widgetApi.setOption('table', …)`. `onRecords` triggers a debounced refresh, which catches column changes in the linked table; changes to other tables need the Refresh button. `renderDiagram()` skips re-rendering when the source is unchanged, and Mermaid is set to `er.useMaxWidth: false` so the canvas zoom handles sizing.
